# 1. Boundary section — the distinction was made, and could not be enforced

## The material

The negative-control corpus was regenerated by three tools in
`dev/tools/phase2_5/corpus_regen/`, each inserting a placeholder into every NC so a
presence-checking rule would stop firing. `regen_nc_envelope.py` describes what it
inserts as *"structurally well-formed, not substantively meaningful."*

Two rules were **initially scoped for the same treatment and did not receive it**.
`regen_nc_consistency.py` records why, in its own docstring:

> W-CON-01 and W-AR-01 — initially scoped to corpus regen — were instead fixed via
> predicate tightening … **injecting placeholder values would violate the factor's
> stated semantics.**

The empirical finding behind it is in `v0512_summary.md:45`: 31 of 35 W-CON-01 NC
firings were on factors marked `scoped-out` or `not-applicable`, which *"legitimately
lack `requiredLevel` and `achievedLevel` by design."* Inserting levels there would
have manufactured a credibility claim the package never made.

## Why this is the sharpest available statement of the boundary

The obvious reading of a placeholder-insertion tool is that a corner was cut. The
record shows the opposite: **the substantive-meaningfulness judgment was made, case
by case, in writing, at the time** — inserted here, refused there, with the reason
recorded and a real rule fix chosen instead.

So the limitation the chapter states is **not** that the distinction was missed. It
is that **nothing in the pipeline can enforce it.** A presence-checking rule sees a
satisfied predicate and cannot ask whether the value means anything. A human held the
line and left a record; the machinery could not have held it and could not have
detected its absence.

That is the necessary-but-not-sufficient boundary stated at its strongest, and it
comes from the project's own committed tooling rather than from a critic.

## The pair it completes

| | Direction | Case |
|---|---|---|
| Evidence present, structure absent | machine cannot see it | **W-AR-05** — the judge writes *"experimental comparators do exist"*; the rule fires because `comparedAgainst` is empty. Both true; the comparator lives in prose ([INV-15 §4](investigations/INV-15-m5-scale-and-phase3-gap-probes.md)) |
| Structure present, evidence absent | machine cannot doubt it | **W-ON-02** — the regenerated control satisfies the rule with a stub the source calls not substantively meaningful ([INV-16](investigations/INV-16-nc-trajectory-decomposition.md)) |

**Structural capture is necessary but not sufficient.** Two independent examples of
one limitation, both from committed records, neither constructed for the argument.
Substantive sufficiency checking is future work, and the MECHANICAL/JUDGMENT
partition already carries the vocabulary for the distinction.

# 2. §4.3.4 — the specificity story, with numbers

## The claim as it currently stands

The catalog's negative-control clean rate rose from **0% to 97.1%**, attributed to a
metric-gated refinement loop.

Both the catalog *and* the negative-control corpus changed over that interval. All
four combinations are now measured.

## The closed table

| | M5 corpus (unpatched) | v0.5.12 hybrid | regenerated holdout |
|---|---|---|---|
| **catalog v0.5.7** | 0/176 = **0.0%** | 0/148 = **0.0%** | 0/171 = **0.0%** |
| **catalog v0.5.15.1** | 8/176 = **4.5%** | — | 166/171 = **97.1%** |

- **Rule refinement alone: 4.5 points.**
- **Corpus regeneration alone: 0.0 points.**
- **Together: 97.1%.**

The gain is **interactive, not additive**. It exists in exactly one cell of four.

## The composition explanation — the part a committee wants

A package counts clean only if **no** rule fires, so the rate is governed by whichever
rule is still firing most. That makes the two axes mutually blocking:

| Axis | Blocked by | Firing | Why that axis cannot clear it |
|---|---|---|---|
| Regenerate the corpus, keep the old catalog | **W-EP-01** | **171/171 = 100%** | no regeneration tool targeted it; it needed the v0.5.8 predicate guard |
| Refine the rules, keep the old corpus | **W-ON-02** | **158/176 = 89.8%** | it was never rule-fixed; it was closed by supplying the field |

**Each axis is blocked by a rule that only the other axis fixes.** W-ON-02 alone caps
rule refinement at 10.2%; W-EP-01 alone forces the corpus axis to zero.

So the widely useful sentence: **the four rules that were genuinely fixed were not the
ones holding the number down.** Four rules went from firing on up to 100% of clean
packages to firing on none, and stayed at zero when re-measured four months later —
that refinement is real and the narrative is entitled to it. It simply was not, by
itself, what produced 97.1%.

## Why the decomposition is trustworthy

Two independent confirmations, both denominator-free or exact:

1. **The 2026-04 labels predict the 2026-08 behaviour with no exceptions.** Every rule
   the contemporaneous record labels a predicate fix measures 0.0% on the fixed
   corpus; every rule it labels corpus regen is unchanged to the decimal.
2. **The reproduction cells reproduce exactly** — 0/176 and 166/171, headline and
   denominator, and all ten per-rule values of the 2026-04 baseline table. A
   four-month-old measurement reproduced by current code against the tagged catalog,
   with no value disagreeing.

## Scope that must travel with the 97.1% wherever it appears

It is measured on negative controls **constructed to carry no catalog-detectable
weakness**, bounded contexts of use included. That construction is correct rather
than convenient: **a true negative for a presence-checking rule must actually have
the property present.** A control omitting the field is not a clean package; it is a
package with that defect.

This scope belongs on the number in **GATE-H3's false-positive clause** as well as in
prose.

## The companion figure, and how to report it

The same catalog scores **8/176 = 4.5%** on the unpatched M5 corpus. **This is a
detection result, not a competing specificity figure.** Those packages genuinely lack
applicability bounds; nobody injected the absence; W-ON-02 reporting it on 158 of 176
is the rule working. The same rule fires on all three published case-study encodings.

Reported as detection, it **supports** the catalog: unbounded contexts of use are
endemic in real evidence, and the instrument says so consistently wherever it looks.
Reported as specificity, it would mislabel a success as a failure.
