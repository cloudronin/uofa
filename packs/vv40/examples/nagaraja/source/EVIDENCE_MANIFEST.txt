# Nagaraja Evidence Folder — Reference Manifest
# Pedicle Screw System under Compression-Bending, ASTM F1717
# Nagaraja S, Loughran G, Baumann AP, Kartikeya K, Horner M.
# "Establishing finite element model credibility of a pedicle screw system
#  under compression-bending: An end-to-end example of the ASME V&V 40
#  standard." Methods 225 (2024) 74-88.
# DOI: 10.1016/j.ymeth.2024.03.003
# Archive: https://osf.io/n4pjz/
# ──────────────────────────────────────────────────────
#
# THE ARTIFACTS ARE NOT IN THIS REPOSITORY, AND THAT IS DELIBERATE.
#
# The evidence for this study is three Ansys Workbench project archives on
# OSF, totalling roughly 412 MB. They are referenced here by URL and digest
# only. Two reasons, and both would apply even if size were not one:
#
#   1. The OSF project states no redistribution licence. Referencing content
#      by hash makes no copy and asks for no permission, while still letting a
#      reader re-fetch the bytes and confirm they are the ones assessed.
#   2. A 405 MB binary in git is a 405 MB binary in every clone, forever.
#
# This is what `uofa evidence seal --source-map` produces and what
# `uofa import --evidence` folds into the package before signing, so the
# digests below end up inside the signature rather than beside it.
#
# FILE LISTING (OSF Storage, three files):
#
#   Ansys_FDAF1717NonCannulated-NoResults.wbpz      3,448,952 bytes
#     sha256:b27ffde3da45df30f6e6a512951f1c88a072ca3eca67a19b90f519ee32d5b905
#     Workbench archive, 85 members. The non-cannulated (validated) construct.
#
#   Ansys_FDAF1717Cannulated-NoResults.wbpz         3,569,070 bytes
#     sha256:08faaa9d4bd8d87533b81a1409d544b3ace65f5b34d63c38abe0b49d0f148730
#     Workbench archive, 85 members. The cannulated construct — the design the
#     paper extends the validated model to without new experimental testing.
#
#   FDA_CannulatedAndSolid_F1717_Model.wbpz       ~405,000,000 bytes
#     sha256: NOT YET COMPUTED — this archive has not been downloaded or
#     inspected. Its dp0/dp4/dpall layout suggests a multi-design-point study
#     and it may be the only one of the three that retains result files.
#     Compute the digest with `uofa evidence seal` before citing it.
#
# Digests above were computed from the files as downloaded from the OSF
# project. Re-derive them before relying on them; that is the entire point of
# a content hash.
#
# WHAT IS AND IS NOT IN THESE ARCHIVES:
#
# Both inspected archives are marked "NoResults" and the label is literal:
# every MECH/ directory is an empty directory entry. There is no ds.dat, no
# solve.out and no file.rst. The archives say so themselves — a stored
# Workbench message records that the project was opened from an archive
# written without solution files, and names each omitted file.
#
# What they DO carry, all readable with no Ansys installation and no licence:
#   * the .wbpj project file (XML) — release, build, addins, and 78 stored
#     solver/session messages spanning 2016-2024
#   * EngineeringData.xml and ten per-system material.engd libraries (MatML)
#   * user_files/DesignPointLog.csv — the DOE parameter table
#   * 46 session journals, a design-point table, and a project cache
# Sealed but not read, because no open reader exists: the Mechanical database
# (.mechdb), the CAD geometry (.agdb / .scdoc) and an HDF5 container.
#
# USAGE:
#   # 1. Download the three archives from https://osf.io/n4pjz/ into a folder.
#   uofa evidence inventory osf-n4pjz/
#   uofa evidence seal osf-n4pjz/ --source-map osf-urls.txt -o evidence.json
#
#   # 2. Extraction proposes; a human adjudicates. Both steps are required.
#   uofa extract osf-n4pjz/ nagaraja-paper.pdf --pack vv40 -o extracted.xlsx
#   [review the spreadsheet — this step is not optional]
#
#   # 3. The digests and stated absences go inside the signature, not beside it.
#   uofa import extracted.xlsx --evidence evidence.json \
#       --sign --key keys/my.key --check
#   uofa verify uofa-nagaraja.jsonld
#
# `osf-urls.txt` is two columns, `filename<space>url`. No per-file URL is
# derived from the collection URL: a fabricated link that 404s would turn a
# re-derivability claim into a dead end, so without a supplied URL the seal
# records digests and no pins, and says so.
