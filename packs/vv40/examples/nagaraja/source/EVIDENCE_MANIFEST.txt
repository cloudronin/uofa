# Nagaraja Evidence Folder — Reference Manifest
# Pedicle Screw System under Compression-Bending, ASTM F1717
# Nagaraja S, Loughran G, Baumann AP, Kartikeya K, Horner M.
# "Establishing finite element model credibility of a pedicle screw system
#  under compression-bending: An end-to-end example of the ASME V&V 40
#  standard." Methods 225 (2024) 74-88.
# DOI: 10.1016/j.ymeth.2024.03.003
# Archive: https://osf.io/n4pjz/
# ──────────────────────────────────────────────────────
#
# THE ARTIFACTS ARE NOT IN THIS REPOSITORY, AND THAT IS DELIBERATE.
#
# The evidence for this study is three Ansys Workbench project archives on
# OSF, totalling 412 MB. They are referenced here by URL and digest only.
# Two reasons, and both would apply even if size were not one:
#
#   1. The OSF project states no redistribution licence. Referencing content
#      by hash makes no copy and asks for no permission, while still letting a
#      reader re-fetch the bytes and confirm they are the ones assessed.
#   2. A 405 MB binary in git is a 405 MB binary in every clone, forever.
#
# This is what `uofa evidence seal --source-map` produces and what
# `uofa import --evidence` folds into the package before signing, so the
# digests below end up inside the signature rather than beside it.
#
# ── FILE LISTING (OSF Storage, three files) ───────────
#
# Every sha256 below is OSF's own published digest, read from
#   https://files.osf.io/v1/resources/n4pjz/providers/osfstorage/?meta=
# and independently confirmed by hashing the downloaded bytes. That
# cross-check matters: it is the one place these digests are tested against a
# source that did not come from this tool.

# ── WHAT IS AND IS NOT IN THESE ARCHIVES ──────────────
#
# NONE OF THE THREE CONTAINS SOLVER RESULTS. All were inventoried; there is
# no .rst, no .rth, no solve.out and no ds.dat in any of them, and every
# MECH/ directory is an empty directory entry — 8, 9 and 19 of them
# respectively. Two archives say so themselves: a stored Workbench message
# records that the project was opened from an archive written without
# solution files, and names each omitted file.
#
# The 405 MB is almost entirely Mechanical databases: six .mechdb files of
# 121, 121, 86, 86, 86 and 50 MB. The mesh, contacts and boundary conditions
# live in there, in a binary format with no open-source reader. They are
# sealed by digest and reported unread, which is the honest outcome.
#
# What the archives DO carry, all readable with no Ansys installation and no
# licence:
#   * the .wbpj project file (XML) — release, build, addins, and the stored
#     solver/session messages (78 in each small archive, 241 in the large one)
#   * EngineeringData.xml and the per-system material.engd libraries (MatML)
#   * user_files/DesignPointLog.csv — the DOE parameter table
#   * Workbench session journals (46, 46 and 51), a design-point table, and a
#     project cache
# Sealed but not read: the Mechanical databases, the CAD geometry
# (.agdb / .scdoc), an HDF5 container, and the saved result figures (PNG).
#
# ── USAGE ─────────────────────────────────────────────
#
#   # 1. Fetch the three archives. `osf-urls.txt` is two columns,
#   #    `filename<space>url`, using the download links above.
#   uofa evidence inventory osf-n4pjz/
#   uofa evidence seal osf-n4pjz/ --source-map osf-urls.txt -o evidence.json
#
#   # 2. Extraction proposes; a human adjudicates. Both steps are required.
#   uofa extract osf-n4pjz/ nagaraja-paper.pdf --pack vv40 -o extracted.xlsx
#   [review the spreadsheet — this step is not optional]
#
#   # 3. The digests and stated absences go inside the signature, not beside it.
#   uofa import extracted.xlsx --evidence evidence.json \
#       --sign --key keys/my.key --check
#   uofa verify uofa-nagaraja.jsonld
#
# No per-file URL is derived from the collection URL: a fabricated link that
# 404s would turn a re-derivability claim into a dead end, so without a
# supplied URL the seal records digests and no pins, and says so.
